01 · Le constat

Pourquoi tes PDF sont moches.

Tu écris un beau HTML. Tu fais ⌘P. Tu sauves en PDF. Le résultat est cassé. Tu n'es pas seul.

Voici les quatre pièges qu'on retrouve dans la plupart des PDF générés depuis HTML, dont les tiens probablement :

  • Espaces blancs énormes au milieu des pages, sans raison apparente. Le numéro de page flotte tout en bas, le contenu se tasse en haut.
  • Coupures malheureuses entre les pages. Un titre seul en bas, son contenu à la page suivante. Une ligne de tableau coupée en deux.
  • Numéros de page en dur ("02 / 10", "03 / 10"...). Tu ajoutes une page, tu dois tout réécrire à la main. Tu finis par oublier.
  • Couleurs qui sautent à l'impression. Le dégradé de la couverture devient blanc. Les fonds colorés disparaissent.

Pourquoi ça arrive

Le navigateur ne sait pas où couper. CSS min-height: 297mm laisse le contenu déborder, Chrome ajoute des pages silencieusement, ta numérotation explose. position: absolute sur le footer crée des trous. page-break-inside: avoid mal placé force des sauts brutaux.

La vraie cause. CSS print n'est pas une option de CSS standard. C'est un sous-système avec ses règles propres (breaks, page-headers, orphans, widows). Sans la recette, on bricole. Avec la recette, ça tient.

Ce que tu vas trouver dans ce guide

  • Cinq règles d'or qui éliminent 90% des problèmes
  • Un script JS court (moins de 20 lignes) pour la numérotation automatique
  • Un skill Claude open source qui applique tout ça pour toi

02 · Les règles d'or

Figer la page, structurer la mise en page.

1La page A4 est figée à 297mm, pas extensible.

Le piège : min-height: 297mm seul. Le contenu peut déborder, Chrome ajoute des pages silencieusement, la numérotation explose. Aucun signal visuel pour te dire "tu as trop écrit".

La règle : combiner height + min-height + max-height: 297mm avec overflow: hidden. Si le contenu déborde, il est tronqué visuellement à l'écran. Tu vois immédiatement qu'il faut splitter en deux pages.

/* La règle d'or */ .page { width: 210mm; height: 297mm; min-height: 297mm; max-height: 297mm; overflow: hidden; page-break-after: always; }
2Structure flexbox content + footer, jamais position absolute.

Le piège : positionner .page-num en position: absolute; bottom: 6mm. Le numéro flotte en bas mais le contenu au-dessus s'aligne en haut. Espace vide entre les deux, visible et moche.

La règle : trois niveaux en flexbox column. Le .page-content prend tout l'espace disponible, le .page-footer se cale en bas via margin-top: auto.

.page { display: flex; flex-direction: column; } .page-content { flex: 1 1 auto; min-height: 0; } .page-footer { margin-top: auto; }

Flexbox column : disposition verticale où les éléments s'empilent. Avec flex: 1 1 auto, un enfant prend tout l'espace restant. Avec margin-top: auto, un autre enfant est poussé en bas.

margin-top: auto (dans un contexte flex) : c'est le poussoir magique. L'élément se cale en bas du conteneur sans avoir besoin de position: absolute.

02 · Les règles d'or (suite)

Numéroter automatiquement.

3Plus jamais de numéro de page en dur.

Le piège : écrire "02 / 10", "03 / 10" à la main dans chaque footer. Tu ajoutes une page, tu dois tout réécrire. Tu déplaces une section, tu casses la numérotation. Tu oublies un footer, le lecteur voit le bug.

La règle : laisser les footers vides avec un attribut data-sheet-num, et un script JS court (moins de 20 lignes) qui compte les pages au chargement et juste avant l'impression.

À éviter

<div class="page-num">02 / 10</div>

À actualiser manuellement à chaque modif de la structure.

À faire

<div class="page-num" data-sheet-num></div>

Vide en HTML. Rempli par le script JS automatiquement.

Le script JS à coller juste avant </body> :

<script> (function () { function pad(n) { return String(n).padStart(2, '0'); } function numberSheets() { var sheets = document.querySelectorAll('.page'); var total = sheets.length; sheets.forEach(function (sheet, index) { var el = sheet.querySelector('[data-sheet-num]'); if (el) el.textContent = pad(index + 1) + ' / ' + pad(total); }); } if (document.readyState === 'loading') { document.addEventListener('DOMContentLoaded', numberSheets); } else { numberSheets(); } window.addEventListener('beforeprint', numberSheets); })(); </script>

Bénéfices :

  • Ajouter, retirer ou déplacer une page : zéro update manuel
  • Pad à deux chiffres ("01 / 13" plutôt que "1 / 13"), typographique
  • beforeprint recalcule juste avant le PDF, garanti à jour
  • Réutilisable pour mentionner le total ailleurs (data-total-pages)

02 · Les règles d'or (fin)

Anti-orphelins et tables propres.

4Empêcher les orphelins de titre.

Le piège : un titre seul en bas de page, son contenu sur la page suivante. Lecteur confus.

La règle : break-after: avoid sur tous les titres et leads. Le navigateur garde le titre solidaire du contenu qui suit.

h1, h2, h3, h4 { break-after: avoid; page-break-after: avoid; } p.lead, .section-eyebrow + h2.section-title { break-after: avoid; } p, li { orphans: 3; widows: 3; }

Orphelin : première ligne d'un paragraphe seule en bas de page.

Veuve : dernière ligne d'un paragraphe seule en haut de page suivante.

orphans / widows (propriétés CSS) : nombre minimum de lignes à garder ensemble. Valeur 3 est confortable.

5Tables : lignes indivisibles, thead répété.

Le piège : un tableau long est coupé entre deux pages, une ligne au milieu. La suite manque son en-tête, illisible.

La règle : break-inside: avoid sur chaque tr, et display: table-header-group sur le thead qui le fait se répéter en haut de la page suivante.

table { break-inside: auto; } table thead { display: table-header-group; } table tr { break-inside: avoid; }

Et la couleur en print ? Ajouter -webkit-print-color-adjust: exact et print-color-adjust: exact dans @media print. Sans ça, Chrome décolore les fonds et les dégradés sautent. Le PDF devient blanc et triste.

03 · Pour aller plus vite

La checklist et le skill.

Tu peux appliquer ces cinq règles à la main dans chaque livrable que tu génères. Ça marche. Mais tu peux aussi installer le skill open source qui le fait pour toi en une commande.

Check-list avant de remettre un livrable PDF

  • Page A4 figée à height/min/max-height: 297mm + overflow: hidden
  • Structure .page > .page-content + .page-footer en flexbox column
  • Footer calé via margin-top: auto (pas position: absolute)
  • break-after: avoid sur tous les titres et leads
  • Tables avec thead { display: table-header-group } et tr { break-inside: avoid }
  • @page { size: 210mm 297mm; margin: 0 }
  • -webkit-print-color-adjust: exact dans @media print
  • Numérotation automatique via JS (data-sheet-num, zéro numéro en dur)
  • Aucun em-dash (tiret cadratin) dans le texte français
  • Chaque page calibrée 80 à 95% de la hauteur A4
